# v0.22 输入调试测试版

安装 KOF98-K12s-v0.22-输入调试.apk。与 v0.21 使用同一签名，可直接覆盖安装。

## 怎么记录

1. 进入游戏，点右上角齿轮或「暂停」，再点「输入调试」。
2. 点「开始记录」，返回游戏试招。画面顶部会显示「输入调试 · 记录中」。
3. 连续试几次有问题的招式；出现没出招时，可回到这个菜单点「标记刚才没出招」，随后继续测试。
4. 再进入「输入调试」，备注角色、站位、招式及成功或失败，例如「右侧草薙京，↓↙←↓↙←＋A，试了 6 次只有 1 次成功」。
5. 点「停止并导出 ZIP」，在系统文件保存器选择「下载」等位置并保存。把生成的 KOF98-input-日期时间.zip 发来即可。

每次录 20～40 秒通常够用，成功和失败的尝试一起录下来便于对比。单次上限 2 分钟；达到记录容量上限也会自动停止。停止后保留已有数据，可重复导出。取消保存或导出失败不会清空数据。

记录暂存在应用内存里，请先导出再退出应用。「重新记录（覆盖本次）」会替换上一段记录。

蓝牙对战可从对战菜单开启记录；菜单打开期间对战继续运行。导出前先离开蓝牙房间，回到启动页的右上角设置进入「输入调试」。离开房间会停止记录并保留数据。

## 导出内容

- trace.jsonl：手机和版本信息、摇杆/按键实际布局、每个触点的位置和时间（包含系统批量发送的历史触点）、摇杆判定和方向队列、逐帧采样结果、实际提交给模拟核心的 1P/2P 按键、暂停/清空/失败标记。
- note.txt：填写的测试备注。
- README.txt：字段、时间基准、方向和按键位的说明。

触点使用游戏画面控件内的像素坐标，向右为 x 正方向，向下为 y 正方向。事件时间、接收时间、采样截止时间均使用 Android uptimeMillis，可以对齐检查延迟、漏采样和方向排队。

`touch` 的 `stick` 是该触点处理后的状态；`poll` 的 `stick` 是该帧取样后的队列状态。用 `lastTouchId` 关联触点与采样，用 `pollId` 关联采样与核心输入。蓝牙模式还记录本机席位和固定延迟帧数；核心输入已经过双方交换。

核心输入表示传入 Bridge.frame 的按键；JNI 按相同位值提供给游戏读取。它不代表游戏已经判定某个必杀技成功，失败标记与测试备注用于帮助定位具体尝试。

这版在 v0.21 的输入算法上增加记录，默认关闭。记录期间不在触屏或游戏线程写文件，导出压缩在后台线程执行。
